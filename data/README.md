## Downloading (read this before re-downloading anything)

Both datasets live on UNSW SharePoint, reachable from the project pages:

- UNSW-NB15: <https://research.unsw.edu.au/projects/unsw-nb15-dataset>
- TON_IoT: <https://research.unsw.edu.au/projects/toniot-datasets>

**Download files individually. Do not use SharePoint's "download folder as zip".** That feature
failed silently on 2026-07-29: it substituted `<name>_Error.txt` stub files for every file it could
not pack and omitted the zips' central directories. The resulting archives are rejected by `unzip`
entirely (readable only with `7z`), and **every** TON_IoT network CSV was missing —
`train_test_network.csv` plus all 23 `Network_dataset_N.csv`. The stubs are easy to miss because the
archives still look plausibly sized.

What is needed, and where:

| Source path | Save as |
| --- | --- |
| UNSW-NB15 → `CSV Files/Training and Testing Sets/UNSW_NB15_training-set.csv` | `raw/UNSW_NB15_training-set.csv` |
| UNSW-NB15 → `CSV Files/Training and Testing Sets/UNSW_NB15_testing-set.csv` | `raw/UNSW_NB15_testing-set.csv` |
| TON_IoT → `Train_Test_datasets/Train_Test_Network_dataset/train_test_network.csv` | `raw/Train_Test_Network.csv` (note the rename) |

Not needed, deliberately skipped: UNSW's `pcap files` (99.1 GB), `Argus Files`, `BRO Files`,
`UNSW-NB15_1..4.csv`, `NUSW-NB15_GT.csv`; TON_IoT's `Raw_datasets` (67.7 GB), `Processed_datasets`,
`SecurityEvents_GroundTruth_datasets`, and the IoT/Linux/Windows telemetry splits. Nothing in this
project parses a packet, and the pre-partitioned CSVs are the documented ML-ready samples.

## Known deviation: TON_IoT normal-class shortfall

The published `train_test_network.csv` does **not** match its own documentation.

`reference/toniot/Statistics of Network Records.xlsx` specifies the train/test network sample as
**461,043 records with `normal` = 300,000**. The file actually served contains **211,043 records
with `normal` = 50,000** — 250,000 normal rows short. All nine attack classes match the documented
counts exactly (20,000 each, plus `mitm` = 1,043 → 161,043 attacks).

This is not a corrupted download: two independent downloads are byte-identical
(`md5 e9c9e8a9…`), the final row is well-formed across all 44 fields, and the attack counts are
exact. It is what upstream publishes.

**Consequence:** the target-era set is attack-heavy (24% normal) while the documented intent is
normal-heavy (65%). Since RQ1 reports degradation *on this set*, the balance is part of the
measurement, not a cosmetic detail. Report the observed balance alongside the headline delta, and
prefer metrics that are explicit about it (per-class F1 / macro-F1 in addition to the headline F1
and ROC-AUC). Reconstructing the documented 461k sample would require 23 further per-file
downloads of `Processed_datasets/Processed_Network_dataset/Network_dataset_N.csv` — out of scope
unless RQ1 proves balance-sensitive.

## Known deviation: TTL statistics unavailable

The proposal promised TTL-based features. **Confirmed from the real header** (all 44 columns of
`Train_Test_Network.csv`, described in `reference/toniot/Network Features-Description.xlsx`): the
TON_IoT network flow CSVs contain **no TTL field of any kind**. The columns are Zeek
`conn.log`/`dns`/`ssl`/`http`/`weird` fields, and Zeek exports no per-flow IP TTL.

TTL is absent from the flow CSVs and recoverable only from the raw packet captures, which is out
of scope for this timeline.

Secondary point, which turns the shortfall into a methodological improvement: UNSW-NB15's attack
traffic was generated by the IXIA PerfectStorm appliance while its normal traffic came from
different hosts, so initial TTL is a **generator fingerprint rather than an attack signal** —
`sttl` is a widely reported near-perfect single-feature discriminator on UNSW-NB15. Including it
would have inflated in-distribution scores and made the cross-era drop look artificially
catastrophic.

## Citation requirements

- **UNSW-NB15** — its license requires citing Moustafa & Slay: the 2015 MilCIS dataset paper and
  the 2016 evaluation paper. The 2016 reference (`[^unsw-eval]`) **must appear inline** in the
  report; pandoc silently drops uncited footnotes, so it will vanish without an error.
- **TON_IoT** — free for academic research in perpetuity, but the project page asks that **all
  eight** of its referenced papers be cited, which is broader than the single Alsaedi et al.
  reference. Reconcile against the proposal's reference list, mindful of the 6-page cap.
